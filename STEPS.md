# Development steps

Run commands from the repository root. Local scripts build and inspect only; none flashes or reboots the tablet.

## 1. Builder

`docker build -t omarchy-p613-builder:llvm19 -f buildenv/Dockerfile .`

Validate Linux/aarch64, clang/LLD and make, recording package versions. The Docker base digest is pinned; Debian package versions are captured for each built image but the apt repository is not snapshot-pinned yet.

After the image builds, run `bash scripts/prepare-linux-source.sh`. It creates/verifies the pinned checkout from Git objects in case-sensitive Linux storage. Do not compile from the macOS checkout.

## 2. Vendor configuration

`bash scripts/kernel-build.sh configure`

Uses sources.lock.json's kernel revision and vendor/atoll-perf_defconfig plus vendor/gta4xlve.config. The resolved .config is in the `omarchy-p613-build-baseline` Docker volume; host logs are under build/kernel-baseline. The initial comparison against the live tablet baseline is recorded in docs/build-records/vendor-config-comparison.json. Review differences before compiling.

## 3. Unchanged-source compile

`bash scripts/kernel-build.sh build`

Uses four jobs by default. Logs live in build/kernel-baseline; outputs remain in the `omarchy-p613-build-baseline` Linux volume to preserve case-sensitive filenames. Review the final exit status, Image, DTBs/DTBO, provenance and source cleanliness. No boot image is generated by this command.

## 4 onward

Follow PLAN.md in sequence. Recovery preparation and hardware testing require evidence unavailable from a source build. Record the next dependency in PROGRESS.md; never advance its checkbox on the strength of a compile alone.

Inspect a completed build:

```sh
docker run --rm --platform linux/arm64 \
  --mount type=volume,src=omarchy-p613-kernel-baseline,dst=/checkout,readonly \
  --mount type=volume,src=omarchy-p613-build-baseline,dst=/out,readonly \
  --mount "type=bind,src=$PWD/scripts/inspect-kernel-build.py,dst=/inspect.py,readonly" \
  omarchy-p613-builder:llvm19 python3 /inspect.py
```

The external DTC override in kernel-build.sh is required for this baseline. Kernel compilation creates raw Image and device-tree blobs, not a flashable boot.img or dtbo.img.
