# P613 native audio bring-up

The main ALSA card is atoll-idp-snd-card, with a separate dspg-dbmdx capture card. Speakers use the vendor QUIN_MI2S_RX/TAS256X route; the tested main microphone uses TX_CDC_DMA_TX_3 with the WCD ADC path. The reference is the saved tablet vendor mixer_paths.xml and the pinned Samsung device tree. The DBMDX voice/wake firmware was missing during boot; its separate voice functionality is not validated by the main-microphone test.

The first bounded ALSA speaker test played alternating left/right tones at 48 kHz, signed 16-bit stereo, peak PCM value 512 (about -36 dBFS). The owner heard both speakers. Eight routing/format controls were restored, with no amplifier gain, boost, limiter or calibration changes. The microphone test captured 160,000 mono samples at 16 kHz while the owner spoke/counted, measured signal levels, deleted the raw audio in tablet RAM and restored seven mixer controls. Only numerical statistics reached the host. No intelligibility or frequency-response claim follows from these measurements.

Revision 11 adds signed Arch alsa-utils, PipeWire, WirePlumber and pipewire-pulse. The account joins the audio group. With P613_ENABLE_AUDIO=1, the root desktop launcher checks the card identity, grants the audio group access to ALSA nodes and enables the two tested routes. The normal user session starts PipeWire, WirePlumber and the PulseAudio-compatible server directly on its existing private D-Bus, without a systemd user manager. Desktop exit stops the user processes and restores all fifteen original mixer controls; restoration was compared control by control.

The PipeWire configuration explicitly exposes p613-speakers (48 kHz stereo) and p613-microphone (48 kHz mono) on hw:0,0. Application capture can be resampled to 16 kHz. WirePlumber's general ALSA, Bluetooth and camera monitors are disabled so it does not guess routes across the many Qualcomm DSP endpoints. This is a fixed built-in speaker/microphone profile, not a complete jack-switching or Bluetooth profile. The [WirePlumber ALSA configuration](https://pipewire.pages.freedesktop.org/wireplumber/daemon/configuration/alsa.html) and [component/profile configuration](https://pipewire.pages.freedesktop.org/wireplumber/daemon/configuration/components_and_profiles.html) document the monitor controls.

PipeWire and PulseAudio-compatible playback both completed. The owner confirmed the final image's alternating tones, speaker volume slider and mute action. Desktop microphone capture returned frames through p613-microphone; the bounded recorder is deliberately interrupted with SIGINT to finalize the file, and raw capture is deleted after measuring it. The shell microphone mute action changes the source mute state and can restore it. Speaker and microphone defaults are visible through the PulseAudio-compatible API.

The worker periodically requires both expected PipeWire nodes alongside shell, home and keyboard health checks. A three-cycle app lifecycle regression and a bounded desktop-session check cover the combined profile. Hardware test 12 records the exact results.

Remaining: wired-headphone playback/jack switching (the owner has no headphones available), microphone quality/intelligibility and channel coverage, DBMDX voice/wake features, longer-load audio stability and suspend/resume. RTKit is not running, so the services use their scheduling fallback; low-latency or real-time performance is not established. An intermittent USB-network stall recovered after reconnecting the tablet cable while Linux remained responsive; that recovery issue also needs further investigation.
